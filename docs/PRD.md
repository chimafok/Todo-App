# Todo 產品與驗收規格

## 2026-10-28 最新增量：分類管理與備註圖片

本節為維護者最新要求，優先於下方舊章節：分類及標籤長按拖拽排序、獨立「批量刪除」按鈕進入多選；備註可透過系統選圖器加入圖片；表單先顯示文字備註，再顯示圖片區（最新位置調整）。系統分類不可刪，刪一般分類前搬移全部任務與系列，刪標籤保留任務，取消或過期預覽零寫入。拖拽放手後保存，保留原上移／下移操作。

圖片工程預設：每項最多8張，原圖25 MiB內，複製轉為最長邊1536／768 KiB內靜態JPEG、移除EXIF與位置，不改原圖。可預覽、縮放及移除，原文字不變；隨草稿、系列與歷史、垃圾桶保留。新版備份格式4／schema9包含引用與去重圖片，讀舊格式1–3，總檔案仍限64 MiB。圖片不上傳雲端，不要求整個相簿權限。這些容量限制為工程選擇，並非維護者另行指定數字。

新增驗收：AC137長按拖拽及持久排序／取消／過期拒絕；AC138批量多選、系統保護、搬移與整批回滾；AC139選圖取消／返回原表單、原圖不變、縮圖放大／移除與文字保留；AC140草稿／重複／快照／垃圾桶圖片保留；AC141schema8升9及格式4完整圖片往返、舊格式相容、缺圖／壞圖拒絕與原子還原。實際驗證依TESTING與當輪結果，不以本清單推定通過。

目前公開版本 1.2.0／code30，Room schema8／備份格式3，可匯入格式1／schema7及格式2／schema8。維護者已於 2026-10-27 確認 1.2.0-dev01 並同意正式簽署及合併 main；來源與測試包對應見 [發布確認紀錄](verification/approval-1.2.0.json)。以下包含歷史工程界線及驗收目標；版本號不表示全部條件已通過。實際已驗範圍以 [TESTING](TESTING.md) 與 [KNOWN-ISSUES](KNOWN-ISSUES.md) 為準。

備份輸出升至格式3／schema8，資料表範圍不變，加入學習進行中狀態契約；支援格式2／schema8、格式1／schema7匯入，舊格式不能冒用新學習狀態。1.1.0不能讀新格式3，需保留原備份。本次正式發布已取得維護者對 dev01 的明確同意，App／建置來源保持一致，正式包沿用原憑證與 com.chimafok.todo。

## 最近行為：空狀態與長按多選

採用先前提案：日期／未安排空區塊改單行灰字，移除任務式大卡片、圖示及第二行說明；真實任務保留卡片；標題旁顯示項數，0項灰色、正數青色標記。一般搜尋／管理的空狀態同樣不使用大卡片，仍保留必要提示文字。分組數量取完整搜尋／篩選及首頁重複投影後結果，不只首50筆；初次讀取未知時顯示省略號，不先假裝0項。

長按多選包含日程、未安排、一般已完成、垃圾桶和重複歷史。長按先選該項，後續長按只加入、不反向取消；多選時點擊切換，結束／返回清除，原多選按鈕保留。完成及作業狀態按鈕仍獨立，沒有批次完成；查詢或處理中禁止舊列操作。搜尋／篩選或頁面脈絡改變清除選取，取消後晚到的非同步結果不重新打開確認框或恢復舊選取。

垃圾桶任務卡與已刪系列列可各自選取：任務全選受目前搜尋／篩選限制，「全選已刪系列」明示是上方全部已刪系列。批次復原先預覽；選系列只復原同次刪除的剩餘紀錄，先前個別刪除者保持刪除，除非亦明確選取。單獨選取的紀錄若所屬系列仍刪除，須一併選系列或先復原所屬系列。永久刪除選系列包含其全部剩餘紀錄（含更早個別刪除者），確認列出去重後實際數量；未選資料保留。過期、版本／成員變更全交易拒絕，復原一般完成項保留原完成時間並沿用既有寬限。

重複總覽可多選系列，全部仍重複中才可批次停止；批次刪除預設停止並刪各系列時區今天之後的未完成，保留今天／過去／全部已完成；包含歷史須另外勾選。系列內可多選單次紀錄移垃圾桶，不暗中改系列模板或停止生成；「全選可操作紀錄」包含目前搜尋全部頁，規則取消項維持唯讀並排除。刪除當前未完成次數仍沿用既有推進規則。

大型ID／revision及預覽保存ViewModel，不放Bundle；旋轉保留原範圍，新程序舊確認失效須重選，不能自動重建破壞範圍。確認前凍結全部版本與成員，在一個Room交易先驗證再寫；系列預覽統一固定一個Instant、各自轉時區算今天，預設刪除確認遇跨日需重新預覽。Bundle只保存小型畫面標記，選取Map與預覽不跨程序自動還原；沒有新增資料表、備份欄位、權限或對手機自動操作。


## 1. 產品目標、使用者與範圍

### 1.1 產品定位

名稱為 **Todo**，原生 Android 個人待辦工具，原始碼與 APK 透過 GitHub 公開，不上架 Play 商店。介面為繁體中文，固定深色科技風，使用協調配色。開發環境與起步步驟見 [DEVELOPMENT](DEVELOPMENT.md)，實際驗證範圍見 [TESTING](TESTING.md)。

目標是以日期日程為主，快速記錄一般待辦及作業、清楚區分「做完但未提交」、可靠提醒，並保有可回溯的完成與循環紀錄。所有日常功能離線可用。

## 2. 資訊架構與互動

### 2.1 導覽

主要導航使用側邊抽屜，包含「日程」「未安排」「已完成」「分類與標籤」「垃圾桶」「設定」六個入口，不使用底部主導航。每次從桌面或背景重新進入 App 回到日程首頁；不記住上次離開頁面。同次前景使用中的旋轉保留操作狀態，外部檔案／權限回呼仍安全接續未完成表單，不遺失輸入。

```text
日程
  今日（永遠顯示；包含逾期未完成項）
  未來有任務的日期 → 向前捲動／日期跳轉
  未安排（列表下方固定可到達入口／區塊）
未安排
  無截止日期的有效未完成待辦
已完成
  已完成（預設分頁：僅一般／非循環作業完成紀錄）
  重複紀錄（按循環系列分組 → 各次發生日期與狀態）
分類與標籤／垃圾桶／設定
```

「重複紀錄」必須是**已完成頁內的分頁**，不混入預設已完成主清單，也不另增頂層主頁。中文標籤固定使用「重複紀錄」，英文識別可用 Recurring Records。

### 2.2 日程與排序（F01）

- 從今天開始向未來顯示；今日即使空白也保留，未來無任務的日期不顯示。可跳至指定日期，日期選擇器週日起算，時間採 24 小時制。
- 同日有時間的任務按時間早至晚，只有日期的排在其後。同時間按建立時間、最後按 ID 穩定排序。
- 逾期未完成項保留原截止日期，投影至今天；不得把原資料改成今日。今天只出現同一項一次。
- 今日內分「逾期」及「今天」；逾期按原日期／時間早至晚。日期但無時間的任務在該日結束後才逾期，有時間的在截止時刻後逾期。
- 未安排項在日程下方另區，並有獨立頁。使用分頁載入與可快速到達的底部區塊，不能要求捲過無限未來日期才能到未安排。
- 跳至空白未來日期時，以暫時日期錨點顯示「當天沒有待辦」及當日新增入口；一般日程仍隱藏空日期。跳到過去顯示該日現存待辦的日期檢視，不更動今日投影規則。

### 2.3 新增與修改（F02）

- 浮動「＋」開啟快速新增，只需名稱；預設分類「未分類」。全域新增不設截止日期，日期區內新增預設該日期。
- 新增／編輯不設二級菜單或「展開／收起詳細設定」：分類、標籤、截止日期／時間、筆記、作業狀態（適用時）、循環與提醒直接依分組呈現，可垂直捲動；未實作功能的欄位隨功能加入，不放假入口。此決定取代產品規則與舊摘要的可展開詳細新增，名稱仍是唯一必填欄位。
- 「建立」成功儲存後關閉；「新增下一項」成功儲存後留在輸入介面。
- 「新增下一項」保留本次新增入口的日期脈絡，其他欄位重設為預設值，避免無意繼承循環及提醒。輸入焦點回名稱。
- 名稱去頭尾空白後不可為空，長度 1–200 字元；筆記上限 20,000 字元。日期可單獨存在，時間必須附日期。驗證錯誤留在原表單，不丟輸入。
- 日期空白提示只寫 YYYY-MM-DD；時間空白提示與解析預覽改為 HH:mm。日期仍接受 YYYY-MM-DD／YYYYMMDD／YYMMDD（固定 20YY）／MMDD，時間接受 HH:mm／HHmm 並兼容 HH-mm，均為 24 小時制；保留選擇器。MMDD 的月日若早於輸入當日，或同日且指定時刻早於當下，使用下一年；只有日期且同日、或同日尚未到時刻，使用當年。明確輸入年份不自動調整。以最後一次輸入／選定日期或時間時記錄的完整 Instant 及當下時區解析；同日比較依該截止的 Instant（含秒及 DST offset），不得只比較年份／日期。旋轉保留參考時刻，僅改名稱／備註不重解；若草稿久留導致截止其後才過期，保存時仍依原預覽警告，不暗中改年。簡寫下方僅預覽解析值；目標年無該日期則拒絕，不進位或跳到數年後。
- 截止早於現在時先警告，確認仍可儲存；返回修改不寫入也不清表單。日期＋時間按保存時區換成 Instant 比較；只有日期按日曆日期判斷，今天不視為已過期，不補午夜。建立／新增下一項／編輯皆適用；旋轉保留待確認狀態，確認時重新驗證完整草稿，版本衝突或其他錯誤仍可拒絕保存。
- 點任務列於原位展開詳情，詳情內有「編輯」。筆記中的 HTTP／HTTPS 網址可點擊開啟；不執行其他 URI scheme。展開只讀，不因展開而保存編輯。
- 一般任務列有完成核取方塊，顯示名稱、分類／標籤、截止日期／時間及逾期提示。沒有滑動完成。
- 儲存中避免連點，儲存成功訊息只能在資料交易完成後出現；失敗時可重試且不得重複建立。
- 完成任務提供短暫勾選／狀態完成回饋、卡片淡出與列表補位；成功回饋在交易提交並觀察到資料後開始，不延後資料寫入。展開／收起詳情、狀態變更及項目移位有短動效，跟隨系統動畫比例，關閉動畫即直接呈現最終狀態。旋轉或離開時可略過裝飾過場，不影響已保存結果。

### 2.4 分類與標籤（F03）

- 每項恰有一分類，可有多個自由標籤。分類及標籤皆可新增、改名、刪除與排序。
- 「未分類」為系統分類，不可改名、刪除；快速新增預設使用它。
- 「作業」為另一系統分類，不可刪除但可改名。作業功能由固定系統識別啟用，不比較顯示名稱。
- 刪除一般分類時提供「移至未分類」「批次移至另一分類」「取消」，不能連帶刪任務。
- 刪分類作用於所有關聯：有效、已完成、垃圾桶內任務及循環模板。分類／標籤的歷史名稱快照不變；歷史連結改指存續分類。若目標是作業分類，必須完成逐項狀態選擇後才一次提交。
- 刪標籤解除其連結，任務保留；修改／排序即時反映。名稱去空白且以大小寫不敏感方式防重複，分類與標籤各自檢查，兩者可同名。系統「未分類」名稱保留。
- 分類／標籤名稱 1–50 字元；管理頁分分類／標籤兩分頁，單項選單提供重新命名、上移、下移與適用的刪除。任務表單直接顯示多選標籤，列表按管理排序顯示。刪分類先選搬移目標；移入作業需逐項選狀態，確認前不落庫，過期任務版本拒絕整筆操作。

### 2.5 作業狀態（F04）

| 狀態值 | 中文顯示 | 列表表現 | 是否屬有效未完成 |
|---|---|---|---|
| NOT_STARTED | 未開始 | 左側空心圓 | 是 |
| IN_PROGRESS | 進行中 | 左側進度環／時鐘，低調文字徽章 | 是 |
| DONE_UNSUBMITTED | 完成未繳交 | 左側文件與待送箭頭，暖色文字徽章 | 是 |
| COMPLETED | 完成 | 左側圈勾；移出有效日程，留完成紀錄 | 否 |

- 作業核取方塊不得修改狀態；用專用狀態控制，支援逐步前進及直接選任一狀態。作業列不顯示一般完成核取方塊，避免誤解。
- 作業狀態放在卡片左側，依當前狀態顯示四種圖示之一，取代右側「狀態」文字按鈕；與一般待辦共用 48dp 控制欄及同一名稱起點。點狀態圖示可任選四態，詳情保留快速前進；圖形與可及性狀態名稱共同表示狀態，不僅靠顏色。
- 快速前進依上表順序；完成代表已完成並提交。通知中的「完成」直接到 COMPLETED，不停在「完成未繳交」。
- 一般任務移入作業分類時，要求選擇四種狀態之一；取消則整次移動不生效。移出作業時，COMPLETED 對應一般已完成，其他三態對應未完成，尤其「完成未繳交」仍是未完成。
- 新作業預設 NOT_STARTED，新增介面可直接選其他任一狀態；重新開啟已完成作業先選狀態，取消則不變更。重新開啟清除目前完成時間，保留原截止日期及穩定 ID。
- 循環作業的新一次一律 NOT_STARTED。

### 2.6 循環任務（F05，日期驅動規則）

1. 支援每日、每週、指定星期、每月、每 N 天，及無限／結束日期／次數三種結束條件；重複日期就是該次截止日期，新作業實例一律未開始。
2. 規則以首次日期為錨點，N 為 1–3650。每月保留原日號，1/31 → 2/28（閏年 2/29）→ 3/31。結束日含當日，次數含第一次及已刪單次。
3. **生成不以前一次完成為條件。** 完成或日期到達均能推進，所有已到發生日期的實例都要補齊並保留原狀態；離線數日後重開也不能遺漏發生紀錄。日期推進以系列時區當日 00:00 為發生日界線；有截止時間時逾期仍按原截止時刻計算。
4. 每個規則槽有唯一 seriesId＋sequenceNo；每次校正生成至今天，必要時僅預備一筆最近未來實例，不預先產生幾個月。完成目前項可提早建立下一槽；重複請求不能增加重複實例。
5. 首頁每系列至多顯示一筆：若有逾期未完成，突出最近逾期；否則選最早待處理項。更早未完成、其他已產生實例全部留在重複紀錄。此規則優先保留「最近逾期」責任，即使有未來項也不覆蓋它；歷史頁可處理每次狀態。
6. 修改僅本次及未來，過去紀錄不變。本次指正在編輯且明示日期的 occurrence；舊紀錄在日期推進退為歷史時就保存快照，不必等完成。規則版本不可覆寫。修改已退休歷史只改該次，不重寫模板。
7. 可刪單次、停止未來重複或刪系列，但不得意外抹除歷史。預設「停止未來重複」保留所有已發生紀錄；「刪除系列」預覽是否包括歷史，預設只停止並把未來待處理項移垃圾桶。只有另行明確選擇包含歷史並確認後才成組刪除，保留 30 天可復原。
8. 重複紀錄按系列分組，含完成及未完成／逾期歷史，不混入已完成主分頁。垃圾桶資料只在垃圾桶顯示；保存歷史狀態及完成是否遲交，不僅一個上次完成時間。
9. 歷史重開／還原不倒轉生成游標，也不停止自動生成；首頁重新按第 5 條選出單一項。每個尚未完成且有效實例都能有使用者原設提醒，首頁隱藏不等於取消提醒，不自增每日催促。
10. 實例生成、狀態改變、游標、快照及提醒期望狀態於同一交易維持一致。系列停止／結束僅阻止未來生成，保留既存未完成、已完成歷史與有效提醒。
11. 「本次及未來」包含序號在本次之後、已生成且尚未退休的未完成項目，以及未生成模板。已完成、已刪除及日期早於其保存時區今天的項目不重排；過去紀錄只可單次編輯。保留 ID、sequence、createdAt 與各次狀態；分類類型轉換依 F04，一般移入作業的其他未完成項從未開始起，移出作業對應 OPEN。未來項名稱／備註／標籤／截止採表單值。
12. 縮短結束條件使既有未來項超出範圍時，標示「規則取消」而非刪除；保留原內容快照與狀態，可在歷史查閱，不進首頁、不完成、不安排提醒。之後延長規則時，符合序號的規則取消項以原 ID／狀態重新啟用；使用者個別刪除的項目不因此復原。游標不退回、不重用槽位，已完成的未來紀錄也不被取消。刪分類搬入作業時，取消項只可對應未開始，不得藉此完成或啟用。
13. 套用前顯示本次日期及其他更新／取消／重新啟用筆數，可返回修改，旋轉保留。確認後同交易重查來源任務、系列與開表單時捕捉的紀錄版本；任一變動或任何寫入失敗全數拒絕／回滾，保留表單。預覽與交易共用規劃函式，不靠畫面筆數直接寫入。

14. 未完成、未刪除的既有非循環任務可在編輯中設定重複，確認後原任務成為第 1 次；保留原 taskId、createdAt 及目前進度，名稱／備註／分類／標籤／截止採表單值。總次數包含這一次，後續新作業一律未開始。無日期必須先填開始日期；指定星期採開始日或之後首個符合日期並在確認中明示。已完成任務須先重開，垃圾桶項不可轉換，不把舊完成歷史改成新系列。
15. 轉換前顯示首次日期、保存時區、目前進度及歷史位置，可返回修改、旋轉保留；過去日期仍先警告。確認後同交易重查原任務 revision、保存原任務、建立系列／規則／模板標籤與 sequence=1 關聯，再校正已到日期；任一步失敗全回滾。過期或重送的轉換不產生第二個系列。第一筆沿用既有 ID，後續仍用確定性 ID；無須新增 schema。

### 2.7 提醒與通知（F06）

最新明確決定（2026-10-23／25，優先於舊表單與舊預設）：截止前提醒以左側整數、右側「分鐘／小時／天」選單設定；固定提醒時間可不填，優先採用截止時間，否則採可調的日期-only 提醒基準（預設 10:00）。儲存時解析並固定 Instant，重新開啟顯示有效時間；之後改截止不改已存固定提醒。提醒在後臺按實際觸發時刻由晚至早排序，從接近截止往前查看；編輯中保持欄位順序穩定，儲存重開才重新排序。單筆與系列沿用此輸入方式，剩餘驗收範圍見 [TESTING](TESTING.md) 與 [KNOWN-ISSUES](KNOWN-ISSUES.md)。

跨時區繼承先將截止時刻換算至該固定提醒捕捉的時區，再取時分搭配提醒日期；基準則使用提醒捕捉時區。時間留空的預覽須清楚顯示實際結果，截止時間缺時區或 DST 不存在時拒絕，不默默猜測。保存後即是獨立固定時刻，只有再次清空時間並儲存才重新繼承。同時刻以建立時間／ID 穩定排序，不刪除截止之後的合法固定提醒。單位是實際時長（天＝1440 分鐘），不是跨 DST 的曆日推算。

- 每項可有多個提醒，與截止日獨立。固定日期時間不隨截止變更；相對提醒以截止**時間**的分鐘偏移計算，截止變更時同步移動。
- 只有截止日期也可設相對提醒，使用可見且可修改的提醒基準時刻，並不替任務填入截止時間。新提醒預設 10:00（既有保存值不變）：截止前一天為前日 10:00；截止前一小時為該日 09:00，表單顯示計算後日期／時刻及可改的 10:00 基準。若無截止日期才要求轉固定或刪相對。移除截止時間時重算前顯示預設基準及預覽，不能靜默假定 23:59。
- 使用 Android 系統聲音與震動設定；不自訂音效、不自動繞過勿擾。完成後取消所有待發提醒；「完成未繳交」仍未完成，因此提醒照常。沒有額外逾期循環催促。
- 優先在允許時精準提醒。Android 13+ 處理通知權限；精準鬧鐘另檢查與引導，兩者獨立。未授權時任務照常保存，顯示提醒能力狀態；不可假裝已可準時通知。參考 [通知權限](https://developer.android.com/develop/ui/compose/notifications/notification-permission) 與 [鬧鐘排程](https://developer.android.com/develop/background-work/services/alarms)。
- 使用 AlarmManager 為每筆提醒設一次性鬧鐘，有精準能力時用適當 exact API，否則以一般鬧鐘退回並顯示「可能延遲」。JobScheduler 僅做維護／校正，不作準點提醒引擎。排程前檢查 `canScheduleExactAlarms()`，處理權限撤銷。
- 重啟後恢復未來提醒，避免補發大量已錯過通知。截止已過不等於提醒失效；只要提醒本身在未來且任務未完成仍安排。過去觸發點標示 MISSED，不補發、不自動挪到現在。
- 通知點擊展開該任務，提供「完成」動作；動作按 occurrence／task ID 套用，重複點擊冪等。舊通知不能完成已推進的新一次。
- 循環相對提醒作為系列模板複製至新一次；「固定時間」若加在系列上，存為相對該次發生日期的日偏移＋時刻，在每次產生時解析為絕對時刻。UI 必須明示「每次發生日之前／當天／之後」。單次固定提醒只屬於該次，不偷偷跨期複製同一個絕對時間。
- 開機解鎖後、App 啟動、套件更新、時間／時區改變、完成、刪除、編輯、還原及匯入後均做冪等 reconcile：取消無效／舊版鬧鐘，恢復符合條件的未來鬧鐘。接收器交付前再讀取資料，避免過期通知。
- 必測 參考 Android 真機 與模擬器；實測須記錄 Android API 與版本。不保證被使用者「強制停止」後仍能提醒；再次開啟後校正。HyperOS 背景／電池設定需實機確認，不能僅靠模擬器宣稱可靠。

工程預設見 [DEVELOPMENT](DEVELOPMENT.md)，已驗證範圍與限制見 [TESTING](TESTING.md)／[KNOWN-ISSUES](KNOWN-ISSUES.md)。0.5.2 的單次／系列模板每項上限 32 個；無日期的相對規則拒絕整筆儲存，原草稿保留。下列增量細則不縮減完整 F06，實機與轉換輸入的驗證範圍以該兩份驗證文件為準。

#### 系列提醒實作細則（0.5.2）

- 系列保存截止前模板及「每次發生日之前／當天／之後」日偏移＋可選時分模板，32 筆上限；日偏移為前後 3650 天，截止前時長沿用十年分鐘上限。時間留空在每次生成時採該次截止時間或可調 10:00 基準。每個實例保存獨立 Reminder／Instant，ID 由 taskId＋templateId 確定，不跨次重用絕對時刻。
- 單次編輯只改本次，改提醒定義時記明確 override；只改名稱、截止或進度不自動變為自訂。系列修改保留單次自訂提醒、過去、已完成及單刪紀錄；本次表單可明確「重設為系列提醒」，重設驗證系列版本。移除全部單次提醒也屬自訂，不因日後模板更新又長回。
- 未改模板定義而只改截止，已生成固定 Instant 不移動，相對提醒移動；明確修改該固定模板／重設時才重新解析。未來新實例依最新模板。自動生成遇 DST 缺口順延、重複時刻採較早 offset，與手動輸入固定日期時間的缺口拒絕不同。
- 本次及未來的規則／模板／任務／提醒／dirty marker 同交易；任一步失敗全回滾，所有已生成相關任務版本需一致。規則取消的任務不發提醒，延長後只重排未來；停止只停止新增，既有未完成項目及其原提醒保留。刪系列取消被刪項目，復原不連帶復原先前單刪者。
- 需要提醒的系列按最大提前量再加兩天緩衝提前建立實例，分批 256 筆，不依完成推進。首頁仍只投影一筆，歷史保留全部 ID。無模板系列維持按日期／完成事件生成。JobScheduler 的持久 15 分鐘維護與 App／時間變更校正共用邏輯，實際通知由已安排的 AlarmManager 負責；背景維護不保證精確到分鐘。失敗系列可重試並不阻擋其他任務現有鬧鐘恢復；系統停止 job 時取消該工作。
- 0.5.3 的明確沿用流程優先於舊版拒絕轉換限制：已有單筆提醒時先按「沿用單筆提醒」，預填系列模板並預覽，再確認保存。這一次保留目前表單的提醒 ID／固定 Instant／時區及未變動的送達終態，記為單次自訂；之後按系列模板產生獨立提醒。原任務 ID／建立時間／作業進度不變。新增草稿亦可沿用，原草稿 ID 採作第 1 次，建立與轉換同交易。
- 相對提醒沿用分鐘偏移及日期-only 基準；固定提醒先換算至系列保存時區，再以首次日期計算曆日偏移與時分，不依裝置目前時區。遇 DST 的後段重複時刻，本次仍保留原 Instant，之後採既定自動模板規則。包含秒／毫秒、超過前後 3650 天或無效資料時明確拒絕沿用，不截斷、不先寫庫。
- 提醒來源、首次日期、截止時間或時區改動後須重新沿用；重新沿用只替換先前映射的模板，保留手動新增項，不重複累加，仍受 32 筆上限。系列模板可再自行修改／移除；確認框分別顯示本次及之後每次的提醒數量。本次自訂不隨系列修改，需明確重設才替換。切回不重複及旋轉均保留兩套草稿；未按沿用、取消確認、版本衝突及任一步寫入失敗不轉換或丟掉原提醒。

### 2.8 搜尋、篩選與批次（F07）

- 日程搜尋有效未完成、已完成頁搜尋歷史、垃圾桶搜尋已刪除；標籤支援 AND／OR。
- 未安排搜尋僅無截止日期的有效項；已完成的主分頁搜尋非循環完成，重複紀錄搜尋已產生循環歷史，保留分頁隔離。搜尋範圍為名稱、筆記、分類名及標籤名，文字大小寫不敏感。
- 多分類採 OR，文字＋分類＋標籤三組之間採 AND。標籤模式明示「符合全部／符合任一」；無選取標籤表示不限制。AND 必須同一任務含全部選取標籤，不能以系列內不同任務湊滿。
- 批次允許移分類、加標籤、刪除；不允許批次完成。全選僅目前搜尋／篩選結果，先顯示數量；改範圍清除選取。垃圾桶的專屬操作是還原／永久刪除，不開放改分類或加標籤。
- 搜尋為去外側空白後的連續子字串，四個欄位任一命中即可；篩選修改先在對話框暫存，套用／清除才生效，取消保留原條件。查詢與選取換頁／回首頁重設，旋轉保留。全選涵蓋結果全部項目，包含尚未捲入畫面的結果；變更條件清空選取，資料更新只剔除已離開範圍的 ID。
- 批次先擷取所選 ID／revision，確認前零寫入，提交時重查全部版本與關聯，一個過期即全拒絕；全部寫入同一交易，中途失敗全回滾。加標籤為聯集，重複不增連結／revision；移分類保留截止、時區與標籤，移入作業逐項選狀態，原已是作業者保留原狀態；移出以是否最終完成映射。批次刪除採軟刪且明示 30 天；0.6.0 已接永久刪除與到期清理；備份仍待 Phase 6 後續。
- 循環目前項的批次移分類／加標籤套用目前及未來模板，歷史快照不變；批次刪除採刪選取單次，整系列須使用明確系列操作，避免意外擴大範圍。

### 2.9 完成、保留與垃圾桶（F08）

- 已完成可以重新開啟；非循環完成記錄按原截止日期分組排序，無截止日期另區，按完成時間新至舊。
- 有日期的完成分組採日期新至舊，組內時間早至晚、只有日期在後；這個方向是規格未指定的預設。只顯示目前為完成的項目，不為每次反覆完成新增重複任務列。
- 一般完成紀錄保留期限可設定，預設永久。選項永久／30／90／365 天及自訂正整數天數，以 completedAt 計算；變更先預覽影響筆數，再確認；提交時重新檢查設定 revision 與受影響任務 ID／revision，時間推進改變筆數亦須重看，任一不符全拒絕。到期先移垃圾桶，deletedAt 採實際移入時間，再保留完整 30 天。此設定**不適用重複歷史**，避免追溯中斷；重複歷史預設永久保存，只依明確刪除操作移除。
- 刪除後在垃圾桶保留 30 天，之後永久移除。精確以 `deletedAt + 30×24h` 為界，App 啟動與維護工作檢查，不依賴 App 常駐；到期後不能還原。允許手動永久刪除，必須確認範圍與數量。
- 還原保留 ID、原截止與狀態，分類已不存在則改為未分類，恢復未來有效提醒、不補發過去提醒。整系列作為一個刪除群組一併還原。單次還原遵循 F05 的單一目前項規則。
- 還原前若垃圾桶刪除群組被部分永久刪除，明示只能還原剩餘資料，不假裝完整。
- 復原的非循環完成項以 max(completedAt, 與這次完成相符的 restoredAt) 計算下一段保留期，不修改原完成時間。重新開啟／再完成是新週期；單純改名稱不撤銷寬限。永久預設不自動清完成紀錄，完成未繳交及未完成不參與完成期限；沒有可信 completedAt 者保留。
- 垃圾桶可逐項永久刪除或清空全部；確認顯示任務與系列筆數，清空明示包含搜尋／篩選隱藏項。提交重查所有版本及全部範圍，不刪有效項，任何錯誤全回滾。永久刪單次不倒退系列 cursor、不再生成舊 ID；父系列仍保留。垃圾桶的空系列仍有明確復原／清空入口，整組復原只包含剩餘同次刪除者；父系列 30 天到期且子項已清完後才移除其規則／模板。
- 永久刪除前同交易保存每筆提醒的 taskId／reminderId／舊 alarmKey 到不帶外鍵的取消佇列；刪除任務及關聯後清除舊 task outbox。排程引擎先重試這個佇列，再處理其餘鬧鐘，成功才移除取消列；失敗仍保存並不阻擋其他鬧鐘恢復。沒有 task outbox 也會處理，資料庫重開不遺失，沒有任務文字留在佇列。
- App 初次進入、前景日期維護及持久 JobScheduler 共用交易清理；單有垃圾桶或有限保留政策也註冊維護，不依賴有提醒／重複。系統可能延後背景工作，過期立即不可還原，下一次可執行維護時實際清除。

### 2.10 備份、匯出、匯入與合併（F09）

- 僅本機、不設帳號及雲端同步。App 內提供檔案匯出／備份及匯入／還原，不加密碼加密。
- 檔案含有效及完成任務、作業狀態、分類、標籤、循環、提醒、垃圾桶、排序與一般設定。備份與資料匯出共用 JSON 格式4；目前一般設定為完成保留期限，不包含未建立草稿與 Android 權限。
- 用 Android 系統檔案選擇器讀寫，不要求廣泛儲存權限；使用者自行選儲存位置。App 本身不做網路傳輸；停用／排除 Android 自動雲端備份的任務資料，避免違反本機限定，依 [官方備份規則](https://developer.android.com/identity/data/autobackup) 配置並驗證。使用者若在系統檔案選擇器主動選雲端位置，屬其指定檔案目的地，App 不另做同步。
- 檔案包含 `formatVersion`、`schemaVersion`、`exportedAt`、`appVersion`、穩定 ID、修改時間及所有關聯。UTF-8 明文；畫面簡短標示檔案可被讀取，讓使用者選合適位置。
- 還原可選「完整取代」或「合併」。取代前呈現目前／匯入的筆數與影響，確認後才交易式置換；取代會清除目前資料庫（含本機垃圾桶），本機一般設定保留。確認對話明示此效果，提供先匯出目前資料入口。
- 合併以唯一 ID 判斷同一任務，修改時間較新者勝出；相同或未知時間且內容不同時詢問使用者。相同 ID、相同內容直接去重；絕不按標題當成同一任務，也不以匯入時間假裝修改時間。
- 系列為一致性聚合：模板、目前指標、規則版本、occurrence 及提醒連結先整組驗證；若逐筆勝出形成矛盾，列為衝突，不能靜默混成損壞系列。衝突畫面提供本機／檔案版本對照，做完選擇後一次提交。
- 系統分類以 `systemKind` 對應本機固定 ID，避免匯入成兩份。一般分類／標籤依 ID 合併；同名不同 ID 保留獨立並在預覽提示，不能偷偷重指派任務。合併與修改使用相同正規化驗證。
- 本機垃圾桶同 ID 與匯入有效資料相撞、或檔案缺少修改時間，需使用者逐項選擇；不自動復活已刪項。已永久刪除且無 tombstone 的 ID 可被舊備份重新匯入，預覽須說明此限制。
- 先離線解析、檢查版本、重複 ID、外鍵、日期、狀態與循環規則，再預覽，再單一交易提交。錯檔、較新不支援格式、使用者取消或任一步失敗，原資料保持完整。匯入成功後才校正提醒，不會立即補發舊提醒。

平台 alarmKey／alarmMode／outbox 不可攜；取代前持久保存舊取消資訊，同 ID 的本機 revision 不倒退。已發／錯過且有效時刻相符的終態保留，其他過去點不補發。取消故障不阻擋其餘提醒。ContentResolver 讀寫以私有暫存 token 接續，旋轉／外部選檔回呼不丟未確認預覽；一般背景返回仍回日程。自動背景匯入不存在，仍須明確確認。

## 3. 時間、視覺與品質規則

### 3.1 時間語意 - 日期用 ISO `LocalDate`，時間用 `LocalTime`，操作時間用 UTC `Instant`，不得把只有日期的任務存成 UTC 午夜。
- 輸入或重新選定日期／時間時記錄當下裝置的 IANA zoneId，含日期入口預填。儲存時不重新抓時區；只改名稱、備註、分類或標籤時保留原截止及時區。明確修改日期或時間代表以當前時區重新設定，表單顯示已記錄時區及截止日對應 UTC offset。舊有日期但無時間、也無時區的資料保持未知，不補造其歷史輸入地點。
- 只有日期的新項可記錄輸入時區作背景資訊，但不生成截止 Instant，日期仍浮動、不移日。有時刻的截止依儲存日期＋時間＋zoneId 解析，裝置換時區不改資料。日程按所在地日期分組／時刻顯示，跨區另列原設定時間與時區，避免漏項或重複；已完成仍依原截止日期分組。固定提醒儲存絕對 Instant；循環按系列時區運算，不因旅行重設系列。
- 今日日期以裝置時區判定；只有日期的逾期依裝置日曆日期，有時刻截止依解析後 Instant。跨午夜前景更新今日投影；跳到過去日期時也不得在今日重複同一列。
- 手動輸入不存在的夏令時間時刻明示錯誤並保留草稿，避免默默換截止時刻；重複時刻取較早 offset，表單可見其 offset。舊資料閱讀保留舊 atZone 解讀；未來循環引擎對自動發生的缺口仍按先前規則取第一個有效時刻。每週／每月不得用固定毫秒加法取代日曆運算。

## 4. 資料模型與不變條件

此節保留領域概念與邏輯不變條件，不是可直接建立資料庫或序列化 JSON 的欄位清單。實際資料表、欄位與 migration 以 [DATA-MODEL](DATA-MODEL.md) 及匯出的 [schema 8](../app/schemas/com.chimafok.todo.data.TodoDatabase/8.json) 核對；JSON 契約以 [BACKUP-FORMAT](BACKUP-FORMAT.md) 為準，不把概念名稱直接當作匯入鍵。

邏輯模型中，`UUID` 以 TEXT、`Instant` 以 UTC epoch 毫秒、日期／時間以 ISO 字串保存。所有使用者可合併實體皆有 `createdAt`、可空相容匯入的 `updatedAt`、`revision`；本機新資料不得缺修改時間。修改 revision 用於擋舊通知／重複請求，時間用於匯入比較。

```text

Category 1 ── N RecurringSeries N ── N Tag（SeriesTag）
RecurringSeries 1 ── N Task（occurrences）
RecurringSeries 1 ── N SeriesRuleVersion
RecurringSeries 1 ── N ReminderTemplate
Task 1 ── N Reminder
DeletionGroup 1 ── N Task／RecurringSeries
```

必要索引：Task(deletedAt,status,dueDate,dueTime)、Task(categoryId)、Task(seriesId,sequenceNo) 唯一、Task(completedAt)、Task(deletionGroupId)、TaskTag(tagId,taskId)、Reminder(taskId)、Reminder(deliveryState,resolvedTriggerAt)、Category(systemKind) 條件唯一、SeriesRuleVersion(seriesId,version) 唯一。名稱正規化防重複在 Repository 驗證；匯入保留的同名異 ID 不可被唯一 name index 意外拒絕。

### 4.3 必須保持的不變條件

1. Task.categoryId 非空、外鍵有效；至少有一個未分類與一個作業系統分類，不以畫面名稱識別。
2. dueTime 非空 → dueDate、zoneId 非空；dueDate 空 → dueTime 空。循環 occurrence 的 dueDate 非空。
3. category.systemKind=ASSIGNMENTS 才能使用作業三種未完成狀態；學習可用 IN_PROGRESS；其他一般分類不可留下進行中或完成未繳交。
4. status=COMPLETED ↔ completedAt 非空；其他狀態 completedAt 為空。完成及清除計時各用正確欄位。
5. 非循環 Task 的 seriesId／sequenceNo 皆空；循環 Task 兩者皆非空。系列 activeTaskId 必須指向同系列、未刪除且未完成的任務。
6. 同系列最多一個首頁 activeTaskId；其他舊未完成紀錄仍保存，既有提醒不因首頁隱藏而取消。STOPPED／ENDED 僅表示不再生成，可保有未完成實例。
7. sequenceNo 與 consumedCount 單調；刪除、清理歷史不能重新使用序號。重開／還原選回既存 ID，不能生一份同日期副本。
8. relative Reminder 要有截止日期，時間空時要有可見可調的 dateOnlyBaseTime；固定與相對欄位互斥。已完成／已刪除不可有有效鬧鐘，其他有效 occurrence 可保有未來提醒。
9. 每個 alarm PendingIntent／通知動作均以穩定 taskId＋reminderId＋revision 識別，不能僅靠可碰撞的 hash requestCode。
10. 所有外部檔案先驗證再落庫；任何錯誤不得留下孤兒分類、缺標籤或指向不存在 activeTask 的系列。

### 4.4 狀態交易範例

**一般完成：** 條件式更新目前未完成 Task → COMPLETED、設 completedAt、寫快照、取消期望提醒、寫 outbox；交易提交後刷新列表與取消鬧鐘。重複完成請求回傳既有結果。

**循環校正／完成：** 依 Clock 與系列時區補齊所有已到日期槽 → 依 taskId 完成指定次（舊通知只能影響原次）→ 必要時預備一筆下一次 → 更新不可回退的游標、快照、首頁投影及提醒期望狀態 → 同交易提交。唯一 seriesId＋sequenceNo 及條件更新確保重試冪等。

**分類移動：** 先取得全部目標與作業狀態選擇 → 同交易轉換分類／狀態／完成時間、更新模板及 outbox。任一選擇取消則整批不做。

**刪除：** 設 deletedAt／群組，停止提醒；單次循環另依上述生成規則推進。**永久刪除**按相依順序移除 reminders／連結／task；系列仍保留生成游標，直到整系列一併永久刪除。

**系列還原：** 同一交易還原模板與群組內存續的 occurrence，保留生成游標並依現時日期及既存狀態重算首頁指標；模板仍在垃圾桶時，不允許單獨把其 occurrence 還原成孤兒。建立／匯入時先插系列（目前指標為空）、規則與 task，再設定 activeTaskId，提交前驗證雙向關聯。

### 4.5 備份檔案契約

實際格式見 [BACKUP-FORMAT](BACKUP-FORMAT.md)，一般操作見 [USER-GUIDE](USER-GUIDE.md#備份與還原)。格式4的根物件包含 `format="Todo-App"`、`formatVersion=4`、`schemaVersion=9`、`exportedAt`（UTC epoch 毫秒）、`appVersion` 及 `data`；十三個資料陣列、嚴格欄位與驗證限制按該契約，不使用本節概念實體名稱代替 JSON 鍵。

匯出包含有效與已刪任務／系列、已完成內容、關聯、歷史快照、提醒、排序與一般設定；不含未建立草稿、私有資料庫檔或 Android 權限。提醒的可攜送達歷史與裝置排程狀態須區分，匯入後重新解析及安排未來提醒。

匯出須有一致資料快照，失敗不顯示成功；匯入先驗證與預覽，確認後在交易中重驗並寫入，任何失敗全回滾。遇未知或矛盾的修改時間須明確選版本，不補成匯入當下。檔案大小、筆數、版本、未知欄位及衝突規則均按實作契約驗證，不另套用早期設計的寬鬆解析。
