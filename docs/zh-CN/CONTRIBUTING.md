# 贡献指南

<p align="center">語言 / 语言 / Languages：<a href="../../CONTRIBUTING.md">繁體中文</a> · <strong>简体中文</strong> · <a href="../en/CONTRIBUTING.md">English</a></p>

欢迎反馈问题或提出修改。本专案由 chimafok 维护，尚未承诺固定回覆或发布时程。

先查看既有 Issues；较大的行为变更请先开 Issue 说明目的。提交贡献表示你有权提交并愿意按本专案 MIT 授权提供自有改动，第三方内容须保留原授权。

<a id="branches-and-merges"></a>
## 分支与合并

公开仓库允许外部贡献者提交 Pull Request，但不授予写入或合并权限。没有本仓库写入权限时，先 fork 到自己的账号，再在 fork 建立工作分支并向本仓库提出 PR。`codex/*` 只是分支命名惯例，其他贡献者可使用清楚的分支名称。

一般功能修改依序进行：

1. 从最新 `dev` 建立短期 `codex/*` 或其他清楚命名的工作分支。
2. 完成程序、文件与必要检查后，建立以 `dev` 为目标的 Pull Request。
3. 由具有合并权限的维护者确认改动范围与检查结果，合并到 `dev` 进行整合验证。
4. 整合验证后交付开发签章的测试 APK，待 chimafok 明确同意对应测试版本后，才正式签署，并由具有合并权限的维护者透过 Pull Request 将对应源代码合并到 `main`，再发布正式 APK。

小型纯文件修正限文字、排版与链接，不涉及程序、设置、CI、依赖、授权条款或执行行为。这类修改可从最新 `main` 开分支，经 Pull Request 与必要检查，由具有合并权限的维护者合并到 `main`，再同步 `dev`。`dev` 可快转时使用快转；如果已有未发布工作，使用 `main` → `dev` 的 Pull Request 整合，不覆写分支。

`main` 必须经 Pull Request 与所需检查，不直接推送或绕过保护。提交 PR 不保证会被接受，CI 通过也不会自动合并或发布 APK。正式 APK 在确认发布时另以 Release 提供；合并文件或源代码不会更新已安装的 App。

GitHub 的实际权限与分支保护设置决定技术上的操作能力，本文件不授予任何权限。即使 GitHub 未要求指定审查者，App 改动仍须取得 chimafok 对测试版本的明确同意，才能正式签署、合并 main 及发布。请以仓库当时的设置为准，不将过去设置当作现况。

- `main`：经检查的发布基准，禁止强制推送或直接删除。
- `dev`：日常整合；全部内容同样公开。
- `codex/*`：独立工作分支，也可使用其他清楚命名的短期分支。

<a id="test-apks-and-release-approval"></a>
## 测试 APK 与发布确认

App 改动先完成必要检查并在 `dev` 整合，再交付使用开发签章的 `.debug` 测试 APK，让 chimafok 自行安装与测试；`.qa` 保留给隔离自动测试。交付须列出版本、来源 commit、APK SHA-256、变更重点、已验证范围与已知限制，让测试结果能对应实际文件。测试版与正式版分开安装、分开存储数据。

待 chimafok 明确同意该测试版本后，才可使用既有正式金钥签署、将对应源代码经 PR 合并到 `main`，并发布正式 APK。确认可在对话或 PR 中表达；发布记录保留对应测试版与确认日期，不公开私人对话。未回覆、CI 通过或要求继续开发，都不能代替发布确认。

同意仅涵盖所测试的 App 改动；若之后再改 App 内容，须重新交付测试 APK 并确认。正式建置仍须核对与已同意来源的对应，并完成 release 变体的必要检查；开发签章的测试成功不能取代正式包的签章、安装或更新验证。APK 作为交付文件，不加入 Git 历史；PR 合并的是源代码。

已授权的分支、修改、测试、提交、推送、PR、合并 `dev` 与测试 APK 交付等常规操作，不逐步重复询问。纯文件小修仍可依上方流程直接经 PR 合并 `main`，不需产生 APK 或另取 App 发布确认。

## 修改与验证

请维持繁中、简中与英文界面一致，保留数据库升级与备份契约。不要清除用户数据来修复 migration；不要把正常 App 当自动测试目标。

纯文件小修检查文字、链接与公开内容，无须在本机重跑全部 App 测试；PR 仍须通过仓库要求的 CI。程序修改执行适合范围的单元测试、建置与 Lint；涉及 UI／交易／排程的修改须补必要 QA 验证。装置测试明确使用 `.qa`，只操作自己的模拟器或已获授权的测试装置。新增测试需验证实际行为，避免只复制实作。

不提交私钥、含私钥的凭证存储档／备份、密码、登入 token、本机路径设置、真实数据库或备份。公开凭证及其指纹用于验证，与私钥不同；本仓库使用文件中的公开指纹，参阅[签章说明](SIGNING.md)。公开截图使用虚构数据。正式 APK 仅随已确认的正式 Releases 发布；测试 APK 可本地交付或清楚标示为测试的 Pre-release，均不放入 Git 历史；CI 不接收正式签章金钥。
